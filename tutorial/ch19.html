第 19 章　用 Querydsl 查询 JPA

查询数据库是获取符合特定条件的信息的必备手段。本章聚焦 Querydsl——从 Java 程序查询数据库的备选方案之一。名字里的 dsl 指 领域特定语言（domain specific language），即专用于特定应用领域的语言——查询数据库就是这样一个领域。

本章的源码工程

只有一个：Ch19/querydsl。运行前先执行 Ch19/Ch19.sql。完整文档见 querydsl.com。

19.1 Querydsl 简介：五种查询方案的取舍

从 Java 程序里查询数据库有多种方案，每种都有自己的问题。理解 Querydsl 的价值，得先把前面四种方案的缺陷摆出来。

19.2 创建一个 Querydsl 应用

19.2.1 配置与 Q 类型

在 pom.xml 里加两个依赖：

querydsl-jpa

在 JPA 应用中使用 Querydsl API 所需。运行时也要。

querydsl-apt（scope: provided）

APT = Annotation Processing Tool（注解处理工具）。它在代码编译前处理 Java 文件中的注解。provided 作用域意味着只在构建期生成 Q 类型时需要它，之后就不需要了，因此不会被打进应用制品。

Ch19/querydsl/pom.xml
<dependency>
    <groupId>com.querydsl</groupId>
    <artifactId>querydsl-jpa</artifactId>
    <version>5.0.0</version>
</dependency>
<dependency>
    <groupId>com.querydsl</groupId>
    <artifactId>querydsl-apt</artifactId>
    <version>5.0.0</version>
    <scope>provided</scope>
</dependency>

<!-- 还需要 Maven APT 插件，它负责在构建过程中生成 Q 类型 -->
<plugin>
   <groupId>com.mysema.maven</groupId>
   <artifactId>apt-maven-plugin</artifactId>
   <version>1.1.3</version>
   <executions>
     <execution>
       <goals><goal>process</goal></goals>
       <configuration>
          <outputDirectory>target/generated-sources/java</outputDirectory>   <!-- A -->
          <processor>com.querydsl.apt.jpa.JPAAnnotationProcessor</processor> <!-- B -->
       </configuration>
     </execution>
   </executions>
</plugin>
A 生成的 Q 类型会放在 target/generated-sources/java 目录。
B 用 JPAAnnotationProcessor 生成 Q 类型。如果项目用的是 Hibernate 原生 API 和注解，就要换成 com.querydsl.apt.hibernate.HibernateAnnotationProcessor。
Ch19/querydsl/src/main/resources/META-INF/persistence.xml
<persistence-unit name="ch19.querydsl">
    <provider>org.hibernate.jpa.HibernatePersistenceProvider</provider>
    <properties>
        <property name="javax.persistence.jdbc.driver" value="com.mysql.cj.jdbc.Driver"/>
        <property name="javax.persistence.jdbc.url"
                  value="jdbc:mysql://localhost:3306/CH19_QUERYDSL?serverTimezone=UTC"/>
        <property name="javax.persistence.jdbc.user" value="root"/>
        <property name="javax.persistence.jdbc.password" value=""/>
        <property name="hibernate.dialect" value="org.hibernate.dialect.MySQL8Dialect"/>
        <property name="hibernate.show_sql" value="true"/>
        <property name="hibernate.format_sql" value="true"/>
        <property name="hibernate.hbm2ddl.auto" value="create"/>
    </properties>
</persistence-unit>
把 show_sql 和 format_sql 都打开

本章会反复对照「Querydsl 代码」和「Hibernate 生成的 SQL」。这两个属性打开后，Hibernate 会漂亮地格式化 SQL 并在字符串里生成注释，让你知道它为什么执行了这条语句。这是学 Querydsl 最有效的方式：写一句，看它变成什么 SQL。

19.2.2 实体

User

@Entity
@NoArgsConstructor
public class User {
    @Id
    @GeneratedValue(generator = Constants.ID_GENERATOR)
    @Getter
    private Long id;

    @Embedded                       // 无独立身份
    @Getter @Setter
    private Address address;

    @OneToMany(mappedBy = "user",
               cascade = CascadeType.ALL)
    private Set<Bid> bids = new HashSet<>();
}

Bid 与 Address

@Entity
@NoArgsConstructor
public class Bid {
    @Id
    @GeneratedValue(generator = Constants.ID_GENERATOR)
    private Long id;

    @ManyToOne(optional = false,
                fetch = FetchType.LAZY)
    @Getter @Setter
    private User user;
}

@Embeddable
@NoArgsConstructor
public class Address { /* Lombok 字段 */ }

还有一个 UserRepository extends JpaRepository<User, Long>——它只用来方便地填充数据库，好让我们有数据可以拿 Querydsl 来查，并不是 Querydsl 的一部分。

19.2.3 测试骨架

Ch19/querydsl/src/test/.../QuerydslTest.java
@ExtendWith(SpringExtension.class)                                    // A
@TestInstance(TestInstance.Lifecycle.PER_CLASS)                        // B
@ContextConfiguration(classes = {SpringDataConfiguration.class})       // C
class QuerydslTest {

    @Autowired                                                        // D
    private UserRepository userRepository;

    private static EntityManagerFactory entityManagerFactory =         // E
                   Persistence.createEntityManagerFactory("ch19.querydsl");

    private EntityManager entityManager;                               // F
    private JPAQueryFactory queryFactory;

    @BeforeAll
    void beforeAll() { userRepository.saveAll(generateUsers()); }      // G

    @BeforeEach
    void beforeEach() {
        entityManager = entityManagerFactory.createEntityManager();
        entityManager.getTransaction().begin();
        queryFactory = new JPAQueryFactory(entityManager);              // H
    }

    @AfterEach
    void afterEach() {                                                 // I
        entityManager.getTransaction().commit();
        entityManager.close();
    }

    @AfterAll
    void afterAll() { userRepository.deleteAll(); }                    // J
}
A 用 SpringExtension 扩展测试——把 Spring 测试上下文与 JUnit 5 Jupiter 测试集成起来（第 20 章会详讲）。
B JUnit 只创建一个测试类实例来执行所有测试，这样才能把 UserRepository 作为实例变量注入。
H 核心两步：JPAQueryFactory 由接受 EntityManager 参数的构造器创建；然后 JPAQueryFactory 再创建 JPAQuery 实例来真正查询数据库。

19.3 用 Querydsl 查询数据库

19.3.1 过滤数据

生成的 Q 类型类各自包含一个自己类型的静态实例：

public static final QUser    user    = new QUser("user");
public static final QBid     bid     = new QBid("bid");
public static final QAddress address = new QAddress("address");

先调 queryFactory.selectFrom(user) 得到一个 JPAQuery 实例，然后用它构建查询的各个子句：where 按给定的 Predicate 过滤，fetchOne 从数据库取单个元素。

fetchOne 的两种边界行为

找不到满足条件的元素 → 返回 null；找到多个满足条件的元素 → 抛 NonUniqueResultException。别把它当 fetchFirst 用。

Querydsl 代码

@Test
void testFindByUsername() {
    User fetchedUser = queryFactory
            .selectFrom(QUser.user)                    // A
            .where(QUser.user.username.eq("john"))     // B
            .fetchOne();                               // C

    assertAll(
        () -> assertNotNull(fetchedUser),
        () -> assertEquals("john",  fetchedUser.getUsername()),
        () -> assertEquals("John",  fetchedUser.getFirstName()),
        () -> assertEquals("Smith", fetchedUser.getLastName()),
        () -> assertEquals(2, fetchedUser.getBids().size()));
}

Hibernate 生成的 SQL

select * from User user0_
where user0_.username=?

-- 第二条来自 getBids()：懒加载集合被触发
select * from Bid bids0_
where bids0_.user_id=?

注意生成了两条 SQL——第二条是访问 fetchedUser.getBids() 时触发的懒加载（第 12 章）。

用 and / or 方法（各接收一个 Predicate）可以按多个条件过滤：

Querydsl 代码

List<User> users = (List<User>) queryFactory
        .from(QUser.user)
        .where(QUser.user.level.eq(3)
        .and(QUser.user.active.eq(true)))
        .fetch();

生成的 SQL

select * from User user0_
where user0_.level=?
  and user0_.active=?

19.3.2 排序数据

用 orderBy 方法——它是重载的，可以接收多个表示排序标准的参数：

Querydsl 代码

@Test
void testOrderByUsername() {
    List<User> users = queryFactory
            .selectFrom(QUser.user)
            .orderBy(QUser.user.username.asc())
            .fetch();

    assertAll(
        () -> assertEquals(users.size(), 10),
        () -> assertEquals("beth",      users.get(0).getUsername()),
        () -> assertEquals("burk",      users.get(1).getUsername()),
        () -> assertEquals("mike",      users.get(8).getUsername()),
        () -> assertEquals("stephanie", users.get(9).getUsername()));
}

生成的 SQL

select * from User user0_
order by user0_.username asc

fetch() 取回 List，fetchOne() 取回单个。

19.3.3 分组与聚合

用 groupBy 方法接收要分组的表达式。这样的查询返回 List<Tuple>——com.querydsl.core.Tuple 对象是一个键/值对，包含用来分组的键和它对应的值。

Ch19/querydsl/src/test/.../QuerydslTest.java
@Test
void testGroupByBidAmount() {
    NumberPath<Long> count = Expressions.numberPath(Long.class, "bids");  // A

    List<Tuple> userBidsGroupByAmount =                                    // B
        queryFactory.select(QBid.bid.amount,
                            QBid.bid.id.count().as(count))                 // C
                    .from(QBid.bid)
                    .groupBy(QBid.bid.amount)                          // D
                    .orderBy(count.desc())                                 // E
                    .fetch();                                              // F

    assertAll(                                                             // G
        () -> assertEquals(new BigDecimal("120.00"),
                    userBidsGroupByAmount.get(0).get(QBid.bid.amount)),
        () -> assertEquals(2, userBidsGroupByAmount.get(0).get(count)));
}
A 把 count() 表达式保存下来，因为构建查询时后面要多次用到它（select 里、orderBy 里、最后取值时）。

生成的 SQL

select
    bid0_.amount    as col_0_0_,
    count(bid0_.id) as col_1_0_
from Bid bid0_
group by bid0_.amount
order by col_1_0_ desc

其他聚合函数

queryFactory.from(QBid.bid)
    .select(QBid.bid.amount.max()).fetchOne();
queryFactory.from(QBid.bid)
    .select(QBid.bid.amount.min()).fetchOne();
queryFactory.from(QBid.bid)
    .select(QBid.bid.amount.avg()).fetchOne();

分别生成 select max(...)、select min(...)、select avg(...)。

19.3.4 子查询与连接

子查询用 JPAExpressions 的静态工厂方法（如 select）创建，再用 from、where 定义参数，最后把子查询传给主查询的 where 方法：

@Test
void testSubquery() {
    List<User> users = queryFactory.selectFrom(QUser.user)               // A
            .where(QUser.user.id.in(                                     // B 子查询作为 where 的参数
                    JPAExpressions.select(QBid.bid.user.id)              // C
                            .from(QBid.bid)
                            .where(QBid.bid.amount.eq(
                                        new BigDecimal("120.00")))))
            .fetch();                                                    // D

    List<User> otherUsers = queryFactory.selectFrom(QUser.user)          // E 同理，105.00
            .where(QUser.user.id.in(
                    JPAExpressions.select(QBid.bid.user.id)
                            .from(QBid.bid)
                            .where(QBid.bid.amount.eq(
                                        new BigDecimal("105.00")))))
            .fetch();

    assertAll(
        () -> assertEquals(2, users.size()),
        () -> assertEquals(1, otherUsers.size()),
        () -> assertEquals("burk", otherUsers.get(0).getUsername()));
}
-- 生成的 SQL
select * from User user0_
where user0_.id in (
    select bid1_.user_id from Bid bid1_ where bid1_.amount=?
)

连接用 innerJoin、leftJoin、outerJoin 定义连接，用 on 方法声明连接条件（一个 Predicate）：

@Test
void testJoin() {
    List<User> users = queryFactory.selectFrom(QUser.user)
            .innerJoin(QUser.user.bids, QBid.bid)                        // B 内连到 Bids
            .on(QBid.bid.amount.eq(new BigDecimal("120.00")))            // C 连接条件
            .fetch();                                                    // D

    List<User> otherUsers = queryFactory.selectFrom(QUser.user)          // E
            .innerJoin(QUser.user.bids, QBid.bid)
            .on(QBid.bid.amount.eq(new BigDecimal("105.00")))
            .fetch();

    assertAll(
        () -> assertEquals(2, users.size()),
        () -> assertEquals(1, otherUsers.size()),
        () -> assertEquals("burk", otherUsers.get(0).getUsername()));
}
-- 生成的 SQL
select * from User user0_
inner join Bid bids1_
    on user0_.id=bids1_.user_id
    and ( bids1_.amount=? )
子查询 vs 连接：同一个问题的两种写法

上面两个测试解决的是同一个问题（找出出价为某金额的用户），断言结果也一模一样，但生成的 SQL 完全不同：一个是 IN (子查询)，一个是 INNER JOIN。哪种更快取决于数据库的优化器和数据分布——而 Querydsl 让你能轻松写出两种版本去实测。

19.3.5 更新实体

用 JPAQueryFactory 的 update 方法，where 定义过滤条件（可选），set 定义要做的修改，execute 真正执行更新。

@Test
void testUpdate() {
    queryFactory.update(QUser.user)                                      // A
            .where(QUser.user.username.eq("john"))                        // B 可选
            .set(QUser.user.email, "john@someotherdomain.com")            // C
            .execute();                                                   // D

    entityManager.getTransaction().commit();                             // E 提交 @BeforeEach 开的事务
    entityManager.getTransaction().begin();                              // F 开新事务，由 @AfterEach 提交

    assertEquals("john@someotherdomain.com",                             // G
            queryFactory.select(QUser.user.email)
                    .from(QUser.user)
                    .where(QUser.user.username.eq("john"))
                    .fetchOne());
}
为什么代码里出现「先 commit 再 begin」这种奇怪顺序

因为 @BeforeEach 已经开了一个事务，@AfterEach 会提交一个事务。要想在同一个测试方法里验证更新已经落库，就得先把当前事务提交掉，再开一个新事务去读——新事务留给 @AfterEach 提交。这就是那对看似倒置的调用的由来。

19.3.6 删除实体（此处有坑）

Querydsl 的一个大问题：DML 忽略 JPA 级联规则

Querydsl 参考文档 2.1.11 节关于 JPA DELETE 查询明确指出：

「JPA 中的 DML 子句不考虑 JPA 层面的级联规则，也不提供细粒度的二级缓存交互。」

因此 User 类中 bids 上 @OneToMany 的 cascade 属性被忽略了：你必须先选出用户、手动删掉他的所有 bid，然后才能用 Querydsl 的 delete 查询删掉这个用户。

额外的佐证：如果改用 userRepository.delete(burk) 来删除用户，@OneToMany 的 cascade 属性就会被正确考虑，完全不需要手工处理该用户的 bid。所以问题确实出在 Querydsl 这一侧。

@Test
void testDelete() {

    User burk = (User) queryFactory.from(QUser.user)
                .where(QUser.user.username.eq("burk"))                     // A 先找到 burk
                .fetchOne();
    if (burk != null) {                        // B 必须手动先删掉他的 bids
        queryFactory.delete(QBid.bid)
                    .where(QBid.bid.user.eq(burk))
                    .execute();
    }

    queryFactory.delete(QUser.user)                                     // C
            .where(QUser.user.username.eq("burk"))                         // D 可选
            .execute();                                                    // E

    entityManager.getTransaction().commit();                               // F
    entityManager.getTransaction().begin();                                // G

    assertNull(queryFactory.selectFrom(QUser.user)                          // H 删掉了就返回 null
            .where(QUser.user.username.eq("burk"))
            .fetchOne());
}
MySQL 上的另一个相关问题

如果只发 delete from User where username=? 这一条 SQL，在 User 有子 Bid 时是不够的。这暴露出另一个 MySQL 特有的问题：Hibernate 创建 schema 时，在 bid 表的 user_id 外键约束上没有加 ON DELETE CASCADE 子句。否则的话，即便 Querydsl 忽略 @OneToMany 的 cascade 属性，这一条 DELETE 也足够了。

Querydsl API 不提供插入能力

没有 queryFactory.insert(...)。要插入实体，请使用 EntityManager（JPA）、Session（Hibernate）或仓库（Spring Data JPA）。Querydsl 是一个查询 DSL，不是一个完整的持久化 API——它和 JPA 是搭配使用而非替代关系。

本章小结

  • SQL、JPQL、Criteria API、Spring Data 等查询方案各有缺陷：缺乏可移植性、缺乏类型安全与静态查询校验、过于啰嗦。Querydsl 抓住了类型安全和可移植性这两个重要理念，同时降低了啰嗦程度。
  • 可以创建一个使用 Querydsl 的持久化应用，定义它的配置和实体，持久化并查询数据。
  • 要使用 Querydsl，需要把它的依赖加进应用。Maven APT（注解处理工具）是必需的——它在构建期创建复制实体的 Q 类型。String → StringPath、Long → NumberPath<Long>，每个 Q 类型都带一个静态实例（QUser.user）。
  • 可以使用 Querydsl 的核心类 JPAQueryFactory 和 JPAQuery 构建查询，来获取、更新和删除数据。JPAQueryFactory 由 EntityManager 构造。
  • 可以创建查询来过滤、排序、分组数据，以及执行连接、更新和删除。分组返回 List<Tuple>；子查询用 JPAExpressions。
  • 三条必须记住的限制：Querydsl 的 DML 忽略 JPA 级联规则（删父前要手动删子）；MySQL 上 Hibernate 生成的外键没有 ON DELETE CASCADE；Querydsl 没有插入能力。
