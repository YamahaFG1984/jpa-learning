2.3.1　配置持久化单元（persistence unit）

什么是持久化单元

持久化单元 = 领域模型类映射 + 一个数据库连接 + 若干配置项。每个应用至少有一个；如果要连多个（逻辑或物理）数据库，就会有多个。它是 JPA 的起点。

Ch02/helloworld/src/main/resources/META-INF/persistence.xml　（位置是标准约定，必须在 classpath 的 META-INF 下）
<persistence xmlns="http://java.sun.com/xml/ns/persistence" … version="2.0">

    <persistence-unit name="ch02">                    ❶ 单元名必须唯一
        <provider>org.hibernate.jpa.HibernatePersistenceProvider</provider>   ❷
        <properties>
            <property name="javax.persistence.jdbc.driver"
                      value="com.mysql.cj.jdbc.Driver"/>                       ❸ 驱动
            <property name="javax.persistence.jdbc.url"
                      value="jdbc:mysql://localhost:3306/CH02?serverTimezone=UTC"/>  ❹ URL
            <property name="javax.persistence.jdbc.user" value="root"/>         ❺ 用户名
            <property name="javax.persistence.jdbc.password" value=""/>         ❻ 密码

            <property name="hibernate.dialect"
                      value="org.hibernate.dialect.MySQL8Dialect"/>              ❼ 方言
            <property name="hibernate.show_sql"   value="true"/>               ❽ 打印 SQL
            <property name="hibernate.format_sql" value="true"/>               ❾ 美化并加注释
            <property name="hibernate.hbm2ddl.auto" value="create"/>            ❿ 每次重建库
        </properties>
    </persistence-unit>
</persistence>
❷ providerJPA 只是规范，必须指出用哪家厂商的 PersistenceProvider 实现。换成 EclipseLink 只改这一行。
❼ hibernate.dialect方言告诉 Hibernate 目标库的 SQL 变体（分页语法、序列支持、类型映射……），这是数据库可移植性的落点。
❽❾ show_sql / format_sql把 Hibernate 实际发出的 SQL 打出来并格式化、附带注释说明「为什么发这条」。学习期务必开着——第 1 章说过，你必须能看懂它发的 SQL。
❿ hbm2ddl.auto=create每次运行都从头重建数据库。适合自动化测试（每次跑测试都有干净的库），绝不能用于生产。

2.3.2　编写持久化类

Ch02/helloworld/src/main/java/com/manning/javapersistence/ch02/Message.java
@Entity                                              ❶ 必须；映射到 MESSAGE 表
public class Message {

    @Id                                              ❷ 必须；标识符属性 → id 列
    @GeneratedValue(strategy = GenerationType.IDENTITY) ❸ 由谁生成 id 值
    private Long id;

    private String text;                              ❹ 普通属性 → text 列

    public String getText() { return text; }
    public void setText(String text) { this.text = text; }
}
为什么这个类如此“普通”很重要

它没有实现任何接口、没有继承任何特殊超类。所以你可以像用普通 Java 类一样用它：

Message msg = new Message();
msg.setText("Hello!");
System.out.println(msg.getText());   // 完全不需要任何容器

这正是 Hibernate 区别于某些持久化方案的关键特性：持久化类可用于任何执行上下文。第 3 章会把这一点提升为「透明持久化」原则。

标识符属性的作用

它让应用能访问持久化实例的数据库标识——主键值。两个 Message 实例若标识符值相同，它们代表数据库中的同一行（回顾第 1 章的“标识问题”）。这里用 Long，但这不是硬性要求，Hibernate 几乎允许任何类型作标识符。

2.3.3　存储与加载消息：一个完整的工作单元

Ch02/helloworld/src/test/java/…/ch02/HelloWorldJPATest.java
public class HelloWorldJPATest {
    @Test
    public void storeLoadMessage() {
        EntityManagerFactory emf =
            Persistence.createEntityManagerFactory("ch02");   ❶ 代表持久化单元；线程安全，全应用共享一个
        try {
            EntityManager em = emf.createEntityManager();       ❷ 开启一次会话 = 所有持久化操作的上下文
            em.getTransaction().begin();                        ❸ 在本线程开启事务

            Message message = new Message();                  ❹ 新建瞬时(transient)实例
            message.setText("Hello World!");

            em.persist(message);                               ❺ 纳入持久化上下文（未必立刻发 SQL！）

            em.getTransaction().commit();                      ❻ 提交 → Hibernate 自动执行 INSERT
            // INSERT into MESSAGE (ID, TEXT) values (1, 'Hello World!')

            em.getTransaction().begin();                       ❼ 只读也要在事务里

            List<Message> messages = em
                .createQuery("select m from Message m", Message.class)  ❽ 这是 JPQL 不是 SQL
                .getResultList();
            // SELECT * from MESSAGE

            messages.get(messages.size() - 1)
                    .setText("Hello World from JPA!");         ❾ 只是改了个 Java 字段…

            em.getTransaction().commit();                      ❿ …提交时脏检查自动发 UPDATE
            // UPDATE MESSAGE set TEXT = 'Hello World from JPA!' where ID = 1

            assertAll(
                () -> assertEquals(1, messages.size()),
                () -> assertEquals("Hello World from JPA!", messages.get(0).getText())
            );
            em.close();                                        ⓫ 谁创建谁关闭
        } finally {
            emf.close();                                       ⓬
        }
    }
}
两个必须记住的点

① 这不是 SQL，是 JPQL。查询串里的 Message 指的不是表名，而是持久化类名 —— 所以它大小写敏感。就算你把这个类映射到别的表名，查询依然照常工作。

② 自动脏检查。Hibernate 检测到 text 属性被改，提交时自动 UPDATE。你不必显式告诉持久化管理器“我改了、去更新数据库吧”。

2.4原生 Hibernate 的引导与配置

可以先跳过

JPA 的配置已经足够标准和丰富，绝大多数应用（包括相当复杂的）都不需要原生引导 API。等你要扩展 Hibernate 类型适配器、添加自定义 SQL 函数时再回来读本节。

对应关系很直接：JPA 的 EntityManagerFactory ⇄ 原生的 org.hibernate.SessionFactory；JPA 的 EntityManager ⇄ 原生的 Session。配置文件可用 hibernate.properties 或 hibernate.cfg.xml（本例用后者，放在 src/test/resources 因为测试要用）。

Ch02/helloworld/src/test/resources/hibernate.cfg.xml
<hibernate-configuration>
    <session-factory>                                     配置的是 SessionFactory 对象
        <property name="hibernate.connection.driver_class">com.mysql.cj.jdbc.Driver</property>
        <property name="hibernate.connection.url">jdbc:mysql://localhost:3306/CH02?serverTimezone=UTC</property>
        <property name="hibernate.connection.username">root</property>
        <property name="hibernate.connection.password"></property>
        <property name="hibernate.connection.pool_size">50</property>   连接池上限
        <property name="show_sql">true</property>
        <property name="hibernate.hbm2ddl.auto">create</property>
    </session-factory>
</hibernate-configuration>
Ch02/helloworld/src/test/java/…/ch02/HelloWorldHibernateTest.java
private static SessionFactory createSessionFactory() {
    Configuration configuration = new Configuration();                     ❶
    configuration.configure().addAnnotatedClass(Message.class);            ❷ configure() 加载 hibernate.cfg.xml
    ServiceRegistry serviceRegistry = new StandardServiceRegistryBuilder()  ❸ 建造者模式
            .applySettings(configuration.getProperties()).build();
    return configuration.buildSessionFactory(serviceRegistry);             ❹
}

@Test
public void storeLoadMessage() {
    try (SessionFactory sessionFactory = createSessionFactory();           ❺ 二者都实现 AutoCloseable
         Session session = sessionFactory.openSession()) {                 ❻
        session.beginTransaction();

        Message message = new Message();
        message.setText("Hello World from Hibernate!");
        session.persist(message);                    ← 方法名和 JPA 一模一样
        session.getTransaction().commit();

        session.beginTransaction();
        CriteriaQuery<Message> criteriaQuery =
            session.getCriteriaBuilder().createQuery(Message.class);       ❼ 这次用 Criteria API
        criteriaQuery.from(Message.class);
        List<Message> messages = session.createQuery(criteriaQuery).getResultList();
        session.getTransaction().commit();
        …
    }
}
ServiceRegistry 是什么

它托管并管理需要访问 SessionFactory 的各类「服务」。服务是为 Hibernate 提供各种功能可插拔实现的类。用建造者模式链式调用来构造这个不可变的注册表。

2.5JPA ⇄ 原生 Hibernate 双向切换

JPA → Hibernate（HelloWorldJPAToHibernateTest）
private static SessionFactory getSessionFactory(
        EntityManagerFactory emf) {
    return emf.unwrap(SessionFactory.class);
}
Hibernate → JPA（HelloWorldHibernateToJPATest）
Configuration cfg = new Configuration();
cfg.configure().addAnnotatedClass(Message.class);

Map<String,String> props = new HashMap<>();
Enumeration<?> names =
    cfg.getProperties().propertyNames();
while (names.hasMoreElements()) {
    String e = (String) names.nextElement();
    props.put(e, cfg.getProperties().getProperty(e));
}
return Persistence
    .createEntityManagerFactory("ch02", props);
全书的使用原则

本书大部分例子不用 SessionFactory / Session。只有当某个特性仅 Hibernate 有（JPA 标准没覆盖）时，才用 unwrap() 切到原生接口 —— 后面章节遇到时会明确指出。

配置类：把负担从代码搬到配置

Ch02/helloworld/src/test/java/…/ch02/configuration/SpringDataConfiguration.java
@EnableJpaRepositories("com.manning.javapersistence.ch02.repositories")  ❶ 扫描该包下的 repository
public class SpringDataConfiguration {

    @Bean
    public DataSource dataSource() {                                    ❷ 数据源 bean
        DriverManagerDataSource ds = new DriverManagerDataSource();
        ds.setDriverClassName("com.mysql.cj.jdbc.Driver");
        ds.setUrl("jdbc:mysql://localhost:3306/CH02?serverTimezone=UTC");
        ds.setUsername("root");  ds.setPassword("");
        return ds;
    }

    @Bean
    public JpaTransactionManager transactionManager(EntityManagerFactory emf) {
        return new JpaTransactionManager(emf);                          ❸ 事务管理器 bean，Spring Data 必需
    }

    @Bean
    public JpaVendorAdapter jpaVendorAdapter() {                        ❹ 厂商适配器：告诉 JPA 怎么跟 Hibernate 打交道
        HibernateJpaVendorAdapter a = new HibernateJpaVendorAdapter();
        a.setDatabase(Database.MYSQL);
        a.setShowSql(true);
        return a;
    }

    @Bean
    public LocalContainerEntityManagerFactoryBean entityManagerFactory() { ❺ 按 JPA 容器引导契约产出 EMF 的工厂 bean
        LocalContainerEntityManagerFactoryBean b =
                new LocalContainerEntityManagerFactoryBean();
        b.setDataSource(dataSource());
        Properties p = new Properties();
        p.put("hibernate.hbm2ddl.auto", "create");
        b.setJpaProperties(p);
        b.setJpaVendorAdapter(jpaVendorAdapter());
        b.setPackagesToScan("com.manning.javapersistence.ch02");        ❻ 扫描实体类所在包
        return b;
    }
}

@ExtendWith(SpringExtension.class)                            ❶ 把 Spring 测试上下文接进 JUnit 5
@ContextConfiguration(classes = {SpringDataConfiguration.class})  ❷ 用上面那个配置类

短在哪里

没有显式创建工厂对象，没有显式控制事务，没有 close()。样板代码被彻底移除，repository 被注入进来即可使用。负担转移到了配置侧 —— 而配置每个应用只做一次。

2.7三种方式的横向对比

框架特点
JPA
  • 使用通用 JPA API，需要一个持久化提供者
  • 可以从配置里切换提供者
  • 需要显式管理 EntityManagerFactory、EntityManager 和事务
  • 配置量与代码量和原生 Hibernate 相当
  • 可由原生 Hibernate 配置构造出 EntityManagerFactory 来切过来
原生
Hibernate
  • 使用原生 Hibernate API，被锁定在这个框架上
  • 配置起于默认文件 hibernate.cfg.xml / hibernate.properties
  • 需要显式管理 SessionFactory、Session 和事务
  • 配置量与代码量和 JPA 相当
  • 可用 unwrap() 从 EMF/EM 得到 SessionFactory/Session 来切过来
Spring
Data JPA
  • 项目里需要额外的 Spring Data 依赖
  • 配置顺带负责创建各种 bean，包括事务管理器
  • repository 只需声明接口，Spring Data 以代理类形式生成实现
  • repository 是注入的，不由程序员显式创建
  • 写的代码最少，因为大部分负担被配置吸收

性能：便利是有代价的

作者在同一台机器（Windows 10、4 核 i7-5500U @2.40GHz、8GB RAM）上，用三种方式跑了 1,000 → 50,000 条记录的 insert / update / select / delete 批量操作：

JPA vs Hibernate四种操作的曲线几乎完全重叠。JPA 虽然在 Hibernate 之上多了一层自己的 API，但这层没有引入任何开销。
Spring Data JPA 的开销insert 从 1,000 条时的约 2 倍涨到 50,000 条时的约 3.5 倍。开销相当可观。
形态差异Hibernate/JPA 的 update、delete 快于 insert；Spring Data JPA 反而慢于 insert。Hibernate/JPA 的 select 随行数增长非常缓慢，Spring Data JPA 的 select 增长很陡。
那什么时候该用 Spring Data JPA？

书中给出两个正当理由：

  1. 项目已经在用 Spring 框架，需要依托它既有的范式（控制反转、自动事务管理等）。
  2. 有强烈的减少代码量、缩短开发时间的诉求——用作者的原话：如今买算力比买程序员便宜。

本章小结

  • Java 持久化项目有三条路：JPA、原生 Hibernate、Spring Data JPA。
  • JPA 路线：persistence.xml 配置持久化单元 → Persistence.createEntityManagerFactory() 拿入口 → EntityManager 做增删改查；靠脏检查自动同步。查询语言是 JPQL（引用类名而非表名）。
  • 原生 Hibernate 路线：hibernate.cfg.xml + Configuration + ServiceRegistry → SessionFactory / Session，API 与 JPA 高度相似。
  • 两条路可双向切换：emf.unwrap(SessionFactory.class)，或把 Hibernate 配置属性传给 Persistence.createEntityManagerFactory(unit, props)。
  • Spring Data JPA 路线：一个 @Configuration 类装配 bean + 一个空的 repository 接口，其余交给自动生成的代理类。
  • 三者的取舍在于可移植性、依赖数量、代码量、执行效率之间的平衡：JPA≈Hibernate 无额外开销；Spring Data JPA 代码最少但运行开销明显。
