第 4 章　使用 Spring Data JPA

这一章把 Spring Data JPA 的能力一次讲透：按方法名生成查询、限制/排序/分页、@Query、投影、修改型查询、Query by Example。后面章节会反复用它作为「另一条访问数据库的路」。

4.1Spring Data JPA 简介

Spring Data 是伞形项目，各子项目与数据库厂商合作开发。目标是：为数据访问提供抽象，同时保留各数据存储的底层特性。本书用到的通用能力有：

  • 通过 JavaConfig 与 XML 配置与 Spring 集成
  • Repository 与自定义对象映射抽象
  • 与自定义 repository 代码集成
  • 基于 repository 方法名的动态查询创建（本章重头戏）
  • 与 Spring Boot 等其他 Spring 项目集成

@TestInstance(PER_CLASS) 的作用

默认情况下 JUnit 5 每个测试方法建一个实例，因此 @BeforeAll/@AfterAll 必须是 static —— 而 static 方法拿不到 @Autowired 的实例字段。改成 PER_CLASS 后二者都能是实例方法，可以直接用注入的 userRepository。

4.5限制结果、排序与分页

first / top两者等价，用来限制结果数量。后面可跟一个可选数字表示最多返回几条；没写数字就是 1。
Pageable / PageRequestPageable 是分页信息的接口，实践中用实现它的 PageRequest，可指定页码、每页大小、排序条件。注意页码从 0 开始。
Sort / Sort.TypedSort / JpaSortSort.by("prop") 按属性名；Sort.TypedSort 用方法句柄（类型安全）；JpaSort.unsafe(...) 允许任意查询内表达式而不只是属性或别名。

4.6流式结果：Streamable

返回多条结果的查询方法可用标准的 Iterable、List、Set。此外 Spring Data 支持 Streamable —— 可以拼接多个 Streamable，并直接对元素做 filter / map。

// UserRepository
Streamable<User> findByEmailContaining(String text);
Streamable<User> findByLevel(int level);

// QueryResultsTest
@Test void testStreamable() {
    try (Stream<User> result =
             userRepository.findByEmailContaining("someother")
                 .and(userRepository.findByLevel(2))     // 拼接两个 Streamable
                 .stream().distinct()) {                 // 转 Stream 并去重
        assertEquals(6, result.count());
    }
}
必须关闭 Stream

这里把 stream 作为 try-with-resources 的资源，会被自动关闭；也可以显式调 close()。否则这个 stream 会一直占着底层数据库连接。

4.7@Query 注解：自己写查询

用了 @Query，方法名就不必遵守任何命名约定。参数可按位置或按名字绑定（@Param）。nativeQuery = true 可写原生 SQL —— 但要清楚这会影响应用的可移植性。

Ch04/springdatajpa2/…/repositories/UserRepository.java
@Query("select count(u) from User u where u.active = ?1")          ❶ 位置参数
int findNumberOfUsersByActivity(boolean active);

@Query("select u from User u where u.level = :level and u.active = :active")
List<User> findByLevelAndActive(@Param("level") int level,             ❷ 具名参数
                                @Param("active") boolean active);

@Query(value = "SELECT COUNT(*) FROM USERS WHERE ACTIVE = ?1",
       nativeQuery = true)                                             ❸ 原生 SQL
int findNumberOfUsersByActivityNative(boolean active);

@Query("select u.username, LENGTH(u.email) as email_length from " +
       "#{#entityName} u where u.username like %?1%")                ❹ SpEL：entityName
List<Object[]> findByAsArrayAndSort(String text, Sort sort);
❷ 为什么要 @Param当你调整方法签名里参数的顺序而忘了同步改查询时，具名参数不会错位。
❹ SpEL 与 #{#entityName}entityName 根据 @Entity 注解解析。因为 UserRepository extends JpaRepository<User, Long>，这里会解析成 User。
QueryResultsTest.java　—— 三种排序写法的对比
List<Object[]> l1 = userRepository.findByAsArrayAndSort("ar",
        Sort.by("username"));                          ❶ 按属性名排序
List<Object[]> l2 = userRepository.findByAsArrayAndSort("ar",
        Sort.by("email_length").descending());          ❷ 按查询里的别名排序
List<Object[]> l3 = userRepository.findByAsArrayAndSort("ar",
        JpaSort.unsafe("LENGTH(u.email)"));            ❸ 按任意表达式排序

assertAll(() -> assertEquals(2, l1.size()),
          () -> assertEquals("darren", l1.get(0)[0]), () -> assertEquals(21, l1.get(0)[1]),
          () -> assertEquals("marion", l2.get(0)[0]), () -> assertEquals(26, l2.get(0)[1]),
          () -> assertEquals("darren", l3.get(0)[0]));
排序对象的三层能力

Sort 里排序的属性必须能解析为查询属性或查询别名（所以 ❷ 里必须在查询中写出 as email_length 这个别名）。JpaSort 继承 Sort，它的 unsafe 属性处理意味着：给的字符串不必是属性或别名，可以是查询内的任意表达式。

4.8投影（Projections）：只取需要的字段

并非总是需要实体的全部属性。前端可以借此减少 I/O，只显示终端用户关心的信息。Spring Data JPA 可以「塑形」返回类型，有选择地返回实体的部分属性。

Ch04/springdatajpa2/…/model/Projection.java　（把逻辑相关的投影归到一个类里）
public class Projection {

    public interface UserSummary {                          // 接口式
        String getUsername();                               // 封闭部分：直接对应属性

        @Value("#{target.username} #{target.email}")         // 开放部分：SpEL 拼接
        String getInfo();
    }

    public static class UsernameOnly {                      // 类式（DTO）
        private String username;
        public UsernameOnly(String username) { this.username = username; }
        public String getUsername() { return username; }
    }
}
UserRepository 上的投影方法
List<Projection.UserSummary>
    findByRegistrationDateAfter(LocalDate date);

List<Projection.UsernameOnly>
    findByEmail(String username);

// 动态投影
<T> List<T> findByEmail(String username, Class<T> type);
ProjectionTest.java
List<Projection.UsernameOnly> users =
    userRepository.findByEmail("john@somedomain.com");
assertEquals("john", users.get(0).getUsername());

List<Projection.UserSummary> sum =
    userRepository.findByRegistrationDateAfter(
        LocalDate.of(2021, Month.FEBRUARY, 1));
assertEquals("julius julius@someotherdomain.com",
             sum.get(0).getInfo());     // ← SpEL 拼出来的

// 同一方法，两种返回

    .findByEmail("mike@…", Projection.UsernameOnly.class);
List<User> b = userRepository
    .findByEmail("mike@…", User.class);

4.9修改型查询（Modifying queries）

用 @Modifying 定义修改方法：INSERT、UPDATE、DELETE 或 DDL 语句。这类方法必须加 @Transactional，或在程序化管理的事务中运行。

Ch04/springdatajpa2/…/repositories/UserRepository.java
@Modifying
@Transactional
@Query("update User u set u.level = ?2 where u.level = ?1")
int updateLevel(int oldLevel, int newLevel);

@Transactional                               ❶ 查询由框架按方法名生成，不需要 @Modifying
int deleteByLevel(int level);

@Transactional
@Modifying
@Query("delete from User u where u.level = ?1")
int deleteBulkByLevel(int level);
修改型查询的价值

它们清楚地强调自己作用于哪些列，并可带条件，因此与「持久化/删除整个对象」相比代码更清晰；而且只改动数据库中有限的几列，执行更快。

4.10Query by Example（QBE）

QBE 是一种不需要写传统查询的查询技术，支持动态构造查询。它由三部分组成：

Ch04/springdatajpa2/src/test/java/…/QueryByExampleTest.java
@Test void testEmailWithQueryByExample() {
    User user = new User();                                  ❶ 探针
    user.setEmail("@someotherdomain.com");

    ExampleMatcher matcher = ExampleMatcher.matching()
            .withIgnorePaths("level", "active")                ❷ 关键！见下方警告
            .withMatcher("email", match -> match.endsWith());

    Example<User> example = Example.of(user, matcher);          ❸
    List<User> users = userRepository.findAll(example);
    assertEquals(4, users.size());
}

@Test void testUsernameWithQueryByExample() {
    User user = new User();
    user.setUsername("J");

    ExampleMatcher matcher = ExampleMatcher.matching()
            .withIgnorePaths("level", "active")
            .withStringMatcher(ExampleMatcher.StringMatcher.STARTING)
            .withIgnoreCase();

    List<User> users = userRepository.findAll(Example.of(user, matcher));
    assertEquals(3, users.size());
}
为什么必须 withIgnorePaths("level", "active")

matcher 会自动忽略所有 null 引用属性。但 level（int）和 active（boolean）是基本类型，不可能为 null —— 如果不显式忽略，它们会带着默认值（0 和 false）进入匹配条件，改变生成的查询。

✓ 带 withIgnorePaths 生成的 SQL
select … from users user0_
where user0_.email like ? escape ?
✓ 第二个测试，带 withIgnorePaths
select … from users user0_
where lower(user0_.username) like ? escape ?
✗ 去掉 withIgnorePaths 后
select … from users user0_
where user0_.active=? and (user0_.email like ? escape ?)
  and user0_.level=0
✗ 第二个测试，去掉后
select … from users user0_
where user0_.active=? and user0_.level=0
  and (lower(user0_.username) like ? escape ?)

多出来的 user0_.active=? and user0_.level=0 会改变查询结果。

本章小结

  • 可以用 Spring Boot 创建并配置 Spring Data JPA 项目：@Entity + 空的 repository 接口 + application.properties。
  • repository 接口层次：Repository → CrudRepository（基础 CRUD）→ PagingAndSortingRepository（排序分页）→ JpaRepository（JPA 专属 + 返回 List）。
  • 查询构建器机制：剥前后缀 → 匹配属性 → 解析谓词，直接把方法名翻译成 JPQL。方法名写错在上下文加载时暴露。
  • 结果限制（first/top）、排序（Sort/TypedSort/JpaSort）、分页（PageRequest，页码从 0 起）、流式（Streamable，用完必须关闭）。
  • @Query 可写 JPQL 或原生 SQL（nativeQuery=true，牺牲可移植性），支持位置/具名参数与 SpEL；更灵活但更不安全（错误运行期才暴露）。
  • 投影塑形返回类型：接口式（封闭可优化 / 开放靠 SpEL）、类式 DTO、以及泛型化的动态投影。
  • 修改型查询用 @Modifying + @Transactional；注意逐条删除（触发回调）与批量删除（单条 JPQL、不触发回调）的取舍。
  • QBE = probe + ExampleMatcher + Example；小心基本类型属性的默认值污染查询条件。
