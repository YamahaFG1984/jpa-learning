第 16 章　使用 Spring Data REST

Spring Data REST 做的事情，用一句话说就是：把你已经写好的 Spring Data 仓库，自动导出成一套 RESTful HTTP 接口——你不写一行 Controller。本章从 REST 的六条架构约束讲起，然后搭一个应用，再依次讲 ETag 条件请求、访问限制、REST 事件、投影与摘录。

本章的三个源码工程

Ch16/spring-data-rest（基础 + ETag + 访问限制）、spring-data-rest-events（REST 事件）、spring-data-rest-projections（投影与摘录）。运行前先执行 Ch16/Ch16.sql。

16.1 REST 应用简介

表述性状态转移（Representational State Transfer，REST）是一种创建 Web 服务的软件架构风格，同时也提供了一组约束。它由美国计算机科学家 Roy Fielding（同时也是 HTTP 规范的作者之一）在 2000 年的博士论文中首次定义。遵循这种风格的 Web 服务被称为 RESTful Web 服务。

客户端（client）

使用 RESTful API 的人或软件。用 API 操作 LinkedIn 的程序员是客户端；你打开 LinkedIn 网站时，浏览器也是客户端。

资源（resource）

API 能获取信息的任何对象。在 LinkedIn API 里，一条消息、一张照片、一个用户都是资源。每个资源都有唯一标识符（URL）。

「无状态」的实际含义

无状态操作不依赖任何先前的操作；它必须包含服务器理解它所需的全部信息。这跟第 10 章讲的持久化上下文（有状态）形成鲜明对照——HTTP 请求之间没有「会话」可言，你不能指望服务器记得上一次你是谁、做了什么。

实体、Bean 与仓库

User 类多了一个 @Version 字段。回忆 11.2.2 节：每当被修改的 User 实例被持久化，这个字段的值就会递增。16.3 节会展示这个字段如何被用作 ETag。

Ch16/spring-data-rest/.../model/User.java 与 Auction.java
@Entity
public class User {
    @Id @GeneratedValue private Long id;

    @Version
    private Long version;              // 乐观锁版本号，同时也是 ETag 的来源

    private String name;
    private boolean isRegistered;
    private boolean isCitizen;
}

// 用户参与拍卖，拍卖由 Auction 类表示：拍卖编号、席位数、参与用户集合
public class Auction {
    private String auctionNumber;
    private int seats;
    private Set<User> users = new HashSet<>();
}

参与拍卖的用户从一个 CSV 文件读入，由 CsvDataLoader 类负责。这里用 @Bean 注解创建一个交给 Spring 管理并注入应用的 bean：

Ch16/spring-data-rest/.../beans/CsvDataLoader.java
public class CsvDataLoader {

    @Bean                                                          // A：方法的返回值成为 Spring 管理的 bean
    public Auction buildAuctionFromCsv() throws IOException {   // B
        Auction auction = new Auction("1234", 20);
        try (BufferedReader reader = new BufferedReader(          // C
             new FileReader("src/main/resources/users_information.csv"))) {
            String line = null;
            do {                                                  // D：逐行读
                line = reader.readLine();
                if (line != null) {
                    User user = new User(line);                    // E
                    user.setIsRegistered(false);
                    auction.addUser(user);
                }
            } while (line != null);
        }
        return auction;                                            // F
    }
}

仓库接口什么都不用写——这正是 Spring Data REST 的魔力所在：

Ch16/spring-data-rest/.../repositories/UserRepository.java
public interface UserRepository extends JpaRepository<User, Long> {

}
Ch16/spring-data-rest/.../Application.java
@SpringBootApplication
@Import(CsvDataLoader.class)                    // A：导入 CsvDataLoader 及它创建的 Auction bean
public class Application {

    @Autowired                                  // B：注入这个 Auction bean
    private Auction auction;

    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }

    @Bean
    ApplicationRunner configureRepository(UserRepository userRepository) {   // C
        return args -> {
            for (User user : auction.getUsers()) {
                userRepository.save(user);
            }
        };
    }
}
ApplicationRunner 是什么

这是 Spring Boot 的一个函数式接口（只有一个抽象方法的接口），能拿到应用的启动参数。这个接口的实例会被创建，并且它的唯一方法会在 SpringApplication.run() 方法即将完成之前被执行——正好用来做数据预填充。

你也可以用 REST 客户端测试（IntelliJ IDEA Ultimate 自带一个，也可以用 cURL 或 Postman）：

GET http://localhost:8081/users/1

16.3 用 ETag 做条件请求

任何跨网络的信息交换都要花时间——信息越小，程序跑得越快。但什么时候、怎样才能减少从服务器取回并在网络上传输的数据量？

假设我们要反复执行同一条 GET http://localhost:8081/users/1。每次都会访问服务器，每次都把同样的信息传一遍——这很低效。

ETag 是 Web 服务器返回的一个 HTTP 响应头。它帮助我们判断某个 URL 上的内容是否被修改过，从而可以发出条件请求。在我们的 User 类里，那个 @Version 字段就会被当作 ETag 使用。

16.4 限制对仓库、方法与字段的访问

Spring Data REST 默认会导出所有 public 的顶层仓库接口。但真实场景经常需要限制对特定方法、字段甚至整个仓库的访问。

Ch16/spring-data-rest/.../repositories/UserRepository.java
@RepositoryRestResource(path = "users")          // A：导出到 /users 路径，这就是默认值
public interface UserRepository extends JpaRepository<User, Long> {

    @Override                                    // B
    @RestResource(exported = false)
    void deleteById(Long id);

    @Override                                    // B
    @RestResource(exported = false)
    void delete(User entity);
}
两个删除方法都要挡

deleteById(Long) 和 delete(User) 是两个不同的方法，必须分别覆写、分别加注解。只挡一个，另一条路依旧敞开。

16.5 使用 REST 事件

有时候需要在特定事件发生时给应用行为加上副作用。REST 应用在处理实体时可以发出 10 种事件，它们全部继承 org.springframework.data.rest.core.event.RepositoryEvent，且都在同一个包下：

16.5.1 写一个 AnnotatedHandler

创建一个 POJO 类，在类上加 @RepositoryEventHandler。这个注解告诉 Spring 管理的 BeanPostProcessor：这个类需要被检查是否含有处理器方法。BeanPostProcessor 会遍历带该注解的类的方法，检测对应不同事件的注解。

事件处理器 bean 必须处于容器控制之下，所以我们把类标注为 @Service（一个 @Component 构造型），这样它就会被 @ComponentScan 或 @SpringBootApplication 扫描到。我们跟踪的是哪个实体的事件，由被注解方法的第一个参数的类型决定。

表 16.1　AnnotatedHandler 注解与对应事件
注解事件
@HandleBeforeCreate / @HandleAfterCreatePOST 事件
@HandleBeforeSave / @HandleAfterSavePUT 与 PATCH 事件
@HandleBeforeDelete / @HandleAfterDeleteDELETE 事件
@HandleBeforeLinkSave / @HandleAfterLinkSave关联对象被保存进仓库
@HandleBeforeLinkDelete / @HandleAfterLinkDelete关联对象从仓库被删除
Ch16/spring-data-rest-events/.../events/UserRepositoryEventHandler.java
@RepositoryEventHandler                     // A：告诉 BeanPostProcessor 来检查处理器方法
@Service                                     // B：纳入容器管理
public class UserRepositoryEventHandler {

    private final static Logger logger =
            Logger.getLogger(UserRepositoryEventHandler.class);

    @HandleBeforeCreate                       // C：关联到 POST 事件
    public void handleUserBeforeCreate(User user) {   // D：第一个参数的类型决定跟踪哪个实体
        if ((user.getName().toUpperCase().charAt(0) >= 'A') &&
            (user.getName().toUpperCase().charAt(0) <= 'M')) {
            logger.info("User " + user.getName() +
                        " is to be created, goes to the first part of the alphabet");
        } else {
            logger.info("User " + user.getName() +
                        " is to be created, goes to the second part of the alphabet");
        }
    }

    @HandleAfterCreate
    public void handleUserAfterCreate(User user) {
        logger.info("I am so tired to have created " + user.getName());
    }

    @HandleBeforeDelete
    public void handleUserBeforeDelete(User user) {
        logger.warn("This is just to let you know that " + user.getName() +
                    " is about to be deleted");
    }

    @HandleAfterDelete
    public void handleUserAfterDelete(User user) {
        logger.warn("Sad but true, " + user.getName() + " has been deleted");
    }
}

16.5.2 写一个 ApplicationListener

第二条路是继承 AbstractRepositoryEventListener 抽象类。这个类按「事件发生在哪个实体上」被泛型化，它会监听事件并调用相应的方法。同样标注 @Service 让容器管理它。

这个抽象类已经包含了一系列空的 protected 方法来应对各种事件，我们只需要覆写并把我们关心的那些改成 public。

表 16.2　ApplicationListener 方法与对应事件
方法事件
onBeforeCreate / onAfterCreatePOST 事件
onBeforeSave / onAfterSavePUT 与 PATCH 事件
onBeforeDelete / onAfterDeleteDELETE 事件
onBeforeLinkSave / onAfterLinkSave关联对象被保存进仓库
onBeforeLinkDelete / onAfterLinkDelete关联对象从仓库被删除
Ch16/spring-data-rest-events/.../events/RepositoryEventListener.java
@Service                                                     // A
public class RepositoryEventListener extends
        AbstractRepositoryEventListener<User> {                 // B：按 User 实体泛型化

    private final static Logger logger =
            Logger.getLogger(RepositoryEventListener.class);

    @Override
    public void onBeforeCreate(User user) {                   // C
        logger.info("I'll make an effort to create this user " + user.getName());
    }

    @Override
    public void onAfterCreate(User user) {
        logger.info("I did my best and I was able to create " + user.getName());
    }

    @Override
    public void onBeforeSave(User user) {
        logger.info("I'll take a breath and I will save " + user.getName());
    }

    @Override
    public void onAfterSave(User user) {
        logger.info("Hard, hard to save " + user.getName());
    }

    @Override
    public void onBeforeDelete(User user) {
        logger.warn("I'll delete " + user.getName() + ", you might never see him/her again");
    }

    @Override
    public void onAfterDelete(User user) {
        logger.warn("Say good-bye to " + user.getName() + ", I deleted him/her");
    }
}

处理器和监听器都会对事件做出反应，产生额外行为作为副作用。

两种方式怎么选？

两种方式提供相似的行为，处理相同类型的事件。在其他条件相同的情况下：

  • 处理器（handler）的优势是只工作在声明层面——类上和方法上的注解而已。
  • 监听器（listener）要求你继承一个已有的抽象类，于是你的类被挂进了一个已存在的层次结构里，类层次设计的自由度就少了（Java 单继承）。

所以默认优先选处理器。

16.6 使用投影与摘录

Spring Data REST 提供了领域模型的默认视图，但真实场景常常需要修改或适配它。可以用投影（projection）和摘录（excerpt）来提供导出信息的特定视图。

先往项目里加一个 Address 类，并希望用 toString 方法来展示它的内容：

Ch16/spring-data-rest-projections/.../model/Address.java
@Entity
public class Address {
    @GeneratedValue @Id private Long id;
    private String street, zipCode, city, state;

    public String toString() {
        return String.format("%s, %s %s, %s", street, zipCode, city, state);
    }
}

User 与 Address 之间是一对一关系，User 里新增一个字段：

@OneToOne(cascade = CascadeType.ALL, orphanRemoval = true)
private Address address;
回顾第 8 章的两个选项

CascadeType.ALL 让持久化操作级联到关联实体；orphanRemoval = true 表示当一个 Address 不再被任何 User 引用时，把它永久删除。

Ch16/spring-data-rest-projections/.../model/UserProjection.java
@Projection(name = "summary", types = User.class)       // A
public interface UserProjection {

    String getName();                                    // B

    @Value("#{target.address.toString()}")                 // C
    String getAddress();
}
A 这个投影名叫 summary，作用于 User 实体。
B 因为字段叫 name，所以要按 getter 命名约定写一个 getName 方法来导出它。
C 按 toString 的展示方式导出地址。这里用了 @Value 注解，里面是一段 Spring 表达式语言（SpEL）。同样要遵守 getter 命名约定，所以方法叫 getAddress。
投影是接口，不是类

你只声明想暴露的 getter，Spring Data REST 会在运行时生成实现。target 在 SpEL 里指代被投影的那个实体实例，所以 #{target.address.toString()} 就是「拿这个 User 的 address，调它的 toString」。

访问 http://localhost:8081/users/1?projection=summary，得到只含 name 和被 toString 格式化过的 address 的视图。若想把这个投影的默认视图应用到整个集合，就回到已定义的仓库上，用 @RepositoryRestResource 的 excerptProjection 选项：

Ch16/spring-data-rest-projections/.../repositories/UserRepository.java
@RepositoryRestResource(path = "users",
                        excerptProjection = UserProjection.class)
public interface UserRepository extends JpaRepository<User, Long> {
}

此后访问 http://localhost:8081/users/，全部用户都按投影定义来展示。

本章小结

  • 用 Spring Boot 可以创建并配置一个 Spring Data REST 项目，为与数据库交互、管理和持久化信息提供一套接口。核心在于：一个空的仓库接口就能自动导出成完整的 REST 端点，你不写 Controller。
  • 可以用 ETag 发出高效的请求：服务器把 @Version 的值作为 ETag 返回，客户端下次带上 If-None-Match，内容没变就只收到 304 + 空响应体，避免传输客户端已经拥有的信息。
  • 可以限制对仓库、方法和字段的访问，只导出你愿意允许的信息和动作：@RepositoryRestResource(exported = false) 挡整个仓库（404）、@RestResource(exported = false) 挡单个方法（405）、@JsonIgnore 挡单个字段。
  • 可以使用 REST 事件并通过处理器和监听器来管理它们：处理器靠元信息（注解）工作，监听器靠继承已有类工作。共 10 种事件，覆盖 Create / Save / Delete / LinkSave / LinkDelete 的 Before 与 After。处理器更优，因为不占用继承位。
  • 可以用投影和摘录为不同用户提供定制化的导出视图：@Projection 定义视图（配合 SpEL 的 @Value），excerptProjection 把它设为集合的默认视图。
