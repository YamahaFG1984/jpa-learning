第 14 章　把 JPA 与 Hibernate 集成进 Spring

本章分析集成 Spring 与 Hibernate 的几种可能。Spring 是轻量但灵活、通用的开源 Java 框架，可用于 Java 应用的任何一层。我们会考察它背后的原理（依赖注入 / 控制反转），并用它配合 JPA 或 Hibernate 构建持久化应用。

14.2用 Spring + DAO 模式构建 JPA 应用

DAO 是什么，以及为什么还要讲它

DAO（data access object）设计模式为数据库创建一个抽象接口，支持访问操作而不暴露数据库的任何内部细节。

「你可能会说我们之前用的 Spring Data JPA repository 已经在做这件事了 —— 确实如此。本章要演示如何手工构建 DAO 类，并讨论什么时候应该优先选择这种方式而不是 Spring Data JPA。」

14.2.1　实体与 DAO 接口

@Entity
public class Item {
    @Id @GeneratedValue(generator = "ID_GENERATOR")

14.2.2　DAO 实现：三个注解各司其职

注解作用
@Repository标记该组件代表一个 DAO。除了把被注解的类标记为 Spring 组件，它还会捕获持久化相关的异常并把它们翻译成 Spring 的非受检异常
@Transactional让类内所有方法都成为事务性的（§11.4.3）
@PersistenceContext(type = PersistenceContextType.EXTENDED)EntityManager 本身不是线程安全的；用 @PersistenceContext 让容器注入一个线程安全的代理对象。把持久化类型设为 EXTENDED，可以让持久化上下文在 bean 的整个生命周期内保持
为什么必须用 EXTENDED？—— 一个具体的报错

所有被注入的 EntityManager bean 都必须用 PersistenceContextType.EXTENDED。如果用默认的 PersistenceContextType.TRANSACTION，返回的对象会在一次事务执行结束时变成游离态；再把它传给 delete 方法，就会得到：

IllegalArgumentException: Removing a detached instance

@Repository
@Transactional
public class ItemDaoImpl implements ItemDao {

    @PersistenceContext(type = PersistenceContextType.EXTENDED)
    private EntityManager em;

    @Override public Item getById(long id) { return em.find(Item.class, id); }

    @Override public List<Item> getAll() {
        return em.createQuery("from Item", Item.class).getResultList();
    }

    @Override public void insert(Item item) {
        em.persist(item);
        for (Bid bid : item.getBids()) em.persist(bid);   // bids 是 @Transient，必须手工持久化
    }

    @Override public void update(long id, String name) {
        Item item = em.find(Item.class, id);
        item.setName(name);
        em.persist(item);
    }

    @Override public void delete(Item item) {
        for (Bid bid : item.getBids()) em.remove(bid);    // 先删所有 bid
        em.remove(item);
    }

    @Override public Item findByName(String name) {
        return em.createQuery("from Item where name=:name", Item.class)
                 .setParameter("name", name).getSingleResult();
    }
}
// BidDaoImpl 结构完全对称，只是操作 Bid，并用 findByAmount 按金额查询

14.2.4　什么时候该用这套方案而不是 Spring Data JPA？

场景说明
①你想把 EntityManager 与事务的控制权交给 Spring（通过控制反转完成）。代价是你失去了调试事务的可能性 —— 请对此有所准备。
②你想创建自己的持久化管理 API，而且不能或不想使用 Spring Data。这可能发生在：你有非常特定、必须自己控制的操作；或者你想去掉 Spring Data 的开销 —— 包括团队上手它所需的爬坡时间、在既有项目里引入新依赖、以及 §2.7 讨论过的 Spring Data 执行延迟。
③某些特定情形下，你希望把 EntityManager 和事务交给 Spring，但仍然不实现自己的 DAO 类。

14.3泛型化 JPA 版：解决 DAO 的三个短板

@Repository
@Transactional
public abstract class AbstractGenericDao<T> implements GenericDao<T> {

    @PersistenceContext(type = PersistenceContextType.EXTENDED)
    protected EntityManager em;        // protected：供子类继承使用
    private Class<T> clazz;              // DAO 实际操作的 Class
    public void setClazz(Class<T> clazz) { this.clazz = clazz; }

    @Override public T getById(long id) {
        return em.createQuery("SELECT e FROM " + clazz.getName() + " e WHERE e.id = :id", clazz)
                 .setParameter("id", id).getSingleResult();
    }
    @Override public List<T> getAll() {
        return em.createQuery("from " + clazz.getName(), clazz).getResultList();
    }
    @Override public void insert(T entity) { em.persist(entity); }
    @Override public void delete(T entity) { em.remove(entity); }

    @Override public void update(long id, String propertyName, Object propertyValue) {
        em.createQuery("UPDATE " + clazz.getName() + " e SET e." + propertyName
                     + " = :propertyValue WHERE e.id = :id")
          .setParameter("propertyValue", propertyValue).setParameter("id", id).executeUpdate();
    }
    @Override public List<T> findByProperty(String propertyName, Object propertyValue) {
        return em.createQuery("SELECT e FROM " + clazz.getName() + " e WHERE e."
                            + propertyName + " = :propertyValue", clazz)
                 .setParameter("propertyValue", propertyValue).getResultList();
    }
}

// 具体子类：只写自己的特殊之处
public class ItemDaoImpl extends AbstractGenericDao<Item> {
    public ItemDaoImpl() { setClazz(Item.class); }
    @Override public void insert(Item item) { em.persist(item); for (Bid b : item.getBids()) em.persist(b); }
    @Override public void delete(Item item) { for (Bid b : item.getBids()) em.remove(b); em.remove(item); }
}
public class BidDaoImpl extends AbstractGenericDao<Bid> {
    public BidDaoImpl() { setClazz(Bid.class); }     // 其余方法全部继承，完全可复用
}

14.4用 Spring + DAO 模式构建 Hibernate 应用

getCurrentSession() vs openSession() —— 必须理解的差别

sessionFactory.getCurrentSession()：如果不存在就创建一个新 Session；否则使用 Hibernate 上下文中已有的 session。事务结束时该 session 会被自动 flush 并 close。

它非常适合单线程应用 —— 用单个 session 会提升性能。但在多线程应用中 session 不是线程安全的，此时应该用 sessionFactory.openSession() 并显式关闭打开的 session；或者因为 Session 实现了 AutoCloseable，用 try-with-resources 块。

…/spring-hibernate-dao/…/dao/ItemDaoImpl.java
@Repository @Transactional
public class ItemDaoImpl implements ItemDao {
    @Autowired
    private SessionFactory sessionFactory;

    @Override public Item getById(long id) {
        return sessionFactory.getCurrentSession().get(Item.class, id);
    }
    @Override public List<Item> getAll() {
        return sessionFactory.getCurrentSession()
                 .createQuery("from Item", Item.class).list();
    }
    @Override public void insert(Item item) {
        sessionFactory.getCurrentSession().persist(item);
        for (Bid bid : item.getBids())
            sessionFactory.getCurrentSession().persist(bid);
    }
    @Override public void update(long id, String name) {
        Item item = sessionFactory.getCurrentSession().get(Item.class, id);
        item.setName(name);
        sessionFactory.getCurrentSession().update(item);
    }
    @Override public void delete(Item item) {      // ← 改用批量删除查询
        sessionFactory.getCurrentSession()
            .createQuery("delete from Bid b where b.item.id = :id")
            .setParameter("id", item.getId()).executeUpdate();
        sessionFactory.getCurrentSession()
            .createQuery("delete from Item i where i.id = :id")
            .setParameter("id", item.getId()).executeUpdate();
    }
    @Override public Item findByName(String name) {
        return sessionFactory.getCurrentSession()
                 .createQuery("from Item where name=:name", Item.class)
                 .setParameter("name", name).uniqueResult();
    }
}

14.5泛型化 Hibernate 版

GenericDao 接口完全不变，只需把 AbstractGenericDao 用 Hibernate API 重写：

@Repository @Transactional
public abstract class AbstractGenericDao<T> implements GenericDao<T> {

    @Autowired
    protected SessionFactory sessionFactory;      // protected：供子类继承使用
    private Class<T> clazz;
    public void setClazz(Class<T> clazz) { this.clazz = clazz; }

    @Override public T getById(long id) {
        return sessionFactory.getCurrentSession()
            .createQuery("SELECT e FROM " + clazz.getName() + " e WHERE e.id = :id", clazz)
            .setParameter("id", id).getSingleResult();
    }
    @Override public List<T> getAll() {
        return sessionFactory.getCurrentSession()
            .createQuery("from " + clazz.getName(), clazz).getResultList();
    }
    @Override public void insert(T entity) { sessionFactory.getCurrentSession().persist(entity); }
    @Override public void delete(T entity) { sessionFactory.getCurrentSession().delete(entity); }
    // update / findByProperty 与 JPA 版结构相同，只是换成 getCurrentSession()
}

本章小结

  • 依赖注入设计模式是 Spring 框架的基础，支撑「由不同组件与对象构成的应用」的创建。框架的关键特征就是控制反转：库由你调用，框架调用你。
  • 可以用 Spring + DAO 模式开发 JPA 应用：Spring 控制 EntityManager、事务管理器和应用使用的其他 bean。注意所有注入的 EntityManager 都要用 PersistenceContextType.EXTENDED。
  • 可以把 JPA 应用泛型化，提供一个通用、易扩展的 DAO 基类：基类含有被所有派生 DAO 继承的公共行为，让它们只实现自己的特定行为。
  • 可以用 Spring + DAO 模式开发 Hibernate 应用：Spring 控制 SessionFactory、事务管理器等 bean。getCurrentSession() 适合单线程；多线程要用 openSession() 并显式关闭。
  • 同样可以把 Hibernate 应用泛型化，得到一个易扩展的 DAO 类层次。
  • 什么时候不用 Spring Data JPA 而手写 DAO：想把 EM/事务交给 Spring 但保留自定义 API；有非常特定、必须自己控制的操作；或想去掉 Spring Data 的团队爬坡成本、新依赖与执行开销。
