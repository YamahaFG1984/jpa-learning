第 17 章　使用 Spring Data MongoDB

面向文档的数据库是 NoSQL 数据库的一种，信息以键/值存储的形式保存。MongoDB 就是这样一个数据库程序。Spring Data MongoDB 作为 Spring Data 大伞项目的一部分，让 Java 程序能够方便地与 MongoDB 文档数据库交互。本章会用两条路线访问 MongoDB：MongoRepository 和 MongoTemplate，并对比它们的优劣与适用场景。

本章的三个源码工程

Ch17/springdatamongodb（MongoRepository、查询、分页、QBE）、springdatamongodb2（DBRef 文档引用）、springdatamongodb3（MongoTemplate）。本章没有 .sql 脚本——数据库不是关系型的，你需要先安装并启动本机的 MongoDB。

17.1 MongoDB 简介

MongoDB 是一个开源的、面向文档的 NoSQL 数据库。它用类 JSON 的文档来存储信息，核心概念有三个：

安装完 MongoDB 后可以打开 MongoDB Compass——一个用于交互和查询 MongoDB 数据库的图形界面。点 Connect 按钮就连上了本地服务器。一个描述 CaveatEmptor 用户的典型 MongoDB 文档长这样：

{
  "_id":{ "$oid":"61c9e17e382deb3ba55d65ac" },
  "username":"john",
  "firstName":"John",
  "lastName":"Smith",
  "registrationDate":{ "$date":"2020-04-12T21:00:00.000Z" },
  "email":"john@somedomain.com",
  "level":1,
  "active":true,
  "_class":"com.manning.javapersistence.springdatamongodb.model.User"
}
两个自动生成的字段

_id 是 MongoDB 的主键，类型是 ObjectId（$oid），所以 Java 侧的 @Id 字段类型是 String 而不是 Long。_class 是 Spring Data MongoDB 自己加的——它记录了这个文档对应哪个 Java 类，反序列化时用来还原正确的类型。

在 Compass 的 Filter 输入框里填查询过滤器就能筛选文档，比如 {"username":"john"}。

17.2 Spring Data MongoDB 简介

Spring Data MongoDB 遵循 Spring Data 的一贯路数：仓库、自定义对象映射抽象、注解、基于仓库方法名的动态查询创建、与其他 Spring 项目及 Spring Boot 的集成。这意味着你在第 4 章、第 15 章学到的东西，绝大部分能直接迁移过来。

关于 Lombok

Lombok 是一个 Java 库，能通过注解自动创建构造器、getter 和 setter，从而减少样板代码。它也有自己的缺点：

  • 需要 IDE 插件才能让 IDE 理解这些注解，否则会报「缺少构造器/getter/setter」
  • 不能在生成的方法里设断点调试（虽然在这些方法里调试的情况很少见）

B Spring Data MongoDB 默认禁用索引创建。把 spring.data.mongodb.auto-index-creation 设为 true 才会启用（否则你写的 @Indexed / @CompoundIndex 全是摆设）。

User 文档类

Ch17/springdatamongodb/.../model/User.java
@NoArgsConstructor
@Document
@CompoundIndexes({
        @CompoundIndex(name = "username_email",
                       def = "{'username' : 1, 'email': 1}"),
        @CompoundIndex(name = "lastName_firstName",
                       def = "{'lastName' : 1, 'firstName': 1}")
})
public class User {

    @Id
    @Getter
    private String id;                 // 注意是 String，对应 MongoDB 的 ObjectId

    @Getter @Setter
    @Indexed(direction = IndexDirection.ASCENDING)
    private String username;

    // 其他带 @Getter / @Setter 的字段

    @Getter @Setter
    @Transient
    private String password;           // 密码不会被存进数据库

    // 另一个构造器

    @PersistenceConstructor
    public User(String username, String firstName, String lastName,
                @Value("#root.ip ?: '192.168.1.100'") String ip) {
        this.username = username;
        this.firstName = firstName;
        this.lastName  = lastName;
        this.ip = ip;
    }
}
@Transient password 字段不会被保存到 MongoDB。很多场景下你都希望密码这类机密信息不被持久化。
@PersistenceConstructor Spring Data MongoDB 从数据库取回信息时会用这个构造器。
@Value("#root.ip ?: '192.168.1.100'") 这是 SpEL 的猫王运算符（Elvis operator）：从数据库取文档时如果 ip 值缺失，就自动采用这个默认值。这正是「动态模式」的现实应对——老文档可能压根没有这个字段。

17.3.1 定义查询方法

Spring Data MongoDB 提供了和 Spring Data JPA 类似的查询构建器机制——根据方法名创建仓库方法的行为。同样地：查询机制会剥掉 find...By、get...By、query...By、read...By、count...By 这样的前后缀，然后解析剩下的部分；同样地，它会看方法的返回类型来决定包装成 Optional 还是 List。

17.3.2 限制结果、排序与分页

和 Spring Data JPA、Spring Data JDBC 一样：first 和 top 关键字（等价）限制结果条数，后跟可选数字，不写则为 1。Pageable 是分页信息接口，实践中用 PageRequest，可指定页号、页大小和排序条件。写法一字不差。

Ch17/springdatamongodb/.../repositories/UserRepository.java
Optional<User> findFirstByOrderByUsernameAsc();
Optional<User> findTopByOrderByRegistrationDateDesc();
Page<User>     findAll(Pageable pageable);
List<User>     findFirst2ByLevel(int level, Sort sort);
List<User>     findByLevel(int level, Sort sort);
List<User>     findByActive(boolean active, Pageable pageable);
class FindUsersSortingAndPagingTest extends SpringDataJdbcApplicationTests {

    @Test
    void testOrder() {
        User user1 = userRepository.findFirstByOrderByUsernameAsc().get();          // A
        User user2 = userRepository.findTopByOrderByRegistrationDateDesc().get();
        Page<User> userPage = userRepository.findAll(PageRequest.of(1, 3));         // B 页号从 0 开始
        List<User> users = userRepository.findFirst2ByLevel(2,                       // C
                                          Sort.by("registrationDate"));
        assertAll(
            () -> assertEquals("beth",   user1.getUsername()),
            () -> assertEquals("julius", user2.getUsername()),
            () -> assertEquals(2, users.size()),
            () -> assertEquals(3, userPage.getSize()),
            () -> assertEquals("beth",   users.get(0).getUsername()),
            () -> assertEquals("marion", users.get(1).getUsername()));
    }

    @Test
    void testFindByLevel() {
        Sort.TypedSort<User> user = Sort.sort(User.class);                          // D 类型安全排序
        List<User> users = userRepository.findByLevel(3,                           // E
                   user.by(User::getRegistrationDate).descending());
        assertAll(
            () -> assertEquals(2, users.size()),
            () -> assertEquals("james", users.get(0).getUsername()));
    }

    @Test
    void testFindByActive() {
        List<User> users = userRepository.findByActive(true,                        // F
                   PageRequest.of(1, 4, Sort.by("registrationDate")));
        assertAll(
            () -> assertEquals(4, users.size()),
            () -> assertEquals("burk", users.get(0).getUsername()));
    }
}

17.3.4 @Query 注解

用 @org.springframework.data.mongodb.repository.Query 可以指定自定义查询，方法名不必遵循任何约定。自定义查询的参数是一个 MongoDB 查询过滤器，可以参数化。两个关键属性：

value

指明要执行的查询过滤器。占位符 ?0 引用方法的第一个参数，?1 引用第二个，以此类推。

fields

指明结果中要包含或排除哪些字段。{field : 1} 表示只包含，{field : 0} 表示排除。

表 17.6　查询操作与对应的 @Query 参数
操作@Query 参数
按某个字段取数据value = { 'field' : ?0 }
按正则表达式取数据value = { 'lastName' : { $regex: ?0 } }
字段大于某参数value = { 'field' : { $gt: ?0 } }
字段大于等于某参数value = { 'field' : { $gte: ?0 } }
字段小于某参数value = { 'field' : { $lt: ?0 } }
字段小于等于某参数value = { 'field' : { $lte: ?0 } }
查询中只包含某个字段fields = "{field : 1}"
查询中排除某个字段fields = "{field : 0}"
Ch17/springdatamongodb/.../repositories/UserRepository.java
@Query("{ 'active' : ?0 }")                                    // A
List<User> findUsersByActive(boolean active);

@Query("{ 'lastName' : ?0 }")                                  // B
List<User> findUsersByLastName(String lastName);

@Query("{ 'lastName' : { $regex: ?0 } }")                       // C 正则匹配
List<User> findUsersByRegexpLastName(String regexp);

@Query("{ 'level' : { $gte: ?0, $lte: ?1 } }")                  // D 两个占位符
List<User> findUsersByLevelBetween(int minLevel, int maxLevel);

@Query(value = "{}", fields = "{username : 1}")               // E 只返回 id 和 username
List<User> findUsernameAndId();

@Query(value = "{}", fields = "{_id : 0}")                     // F 排除 id
List<User> findUsersExcludeId();

@Query(value = "{'lastName' : { $regex: ?0 }}", fields = "{_id : 0}")   // G 两者结合
List<User> findUsersByRegexpLastNameExcludeId(String regexp);
E value 是 {} 所以选中所有用户；fields 是 {username : 1} 所以只返回 id 和 username 字段。注意 _id 默认总是返回的，除非显式排除。
F 选中所有用户，并把 id 从返回字段中排除。

17.4 Query by Example（QBE）

QBE 在第 4 章讲 Spring Data JPA 时讨论过。它是一种不需要写传统查询来包含实体和属性的查询技术，支持动态创建查询，由三部分组成：

Ch17/springdatamongodb/src/test/.../QueryByExampleTest.java
User probe = new User(null, null, "Smith");                // A：只设了 lastName
List<User> result = userRepository.findAll(Example.of(probe));   // B
assertThat(result).hasSize(2)                                    // C
        .extracting("username").contains("john", "burk");
Ch17/springdatamongodb/src/test/.../QueryByMatcherTest.java
ExampleMatcher matcher = ExampleMatcher.matching()
                                       .withIgnorePaths("level")       // A
                                       .withIgnorePaths("active");

User probe = new User();                                      // B
probe.setLastName("Smith");
List<User> result = userRepository.findAll(Example.of(probe, matcher));   // C

assertThat(result).hasSize(2)                                  // D
        .extracting("username").contains("john", "burk");
基本类型（primitive）必须显式忽略

匹配器会自动忽略任何 null 引用属性，但基本类型没有 null。如果不显式忽略 level（int）和 active（boolean），它们会带着默认值 0 和 false 进入匹配器，改变生成的查询——你会莫名其妙地只查到 level 为 0 且未激活的用户。

17.5 引用其他 MongoDB 文档

先说清楚 Spring Data MongoDB 不支持什么

Spring Data MongoDB 不支持我们在关系数据库里考察的那种一对一、一对多、多对多关系。这个框架也不支持把一个文档嵌入另一个文档。

但是——一个文档可以通过 DBRef 引用另一个文档。DBRef 会包含集合名和另一个文档的 ID 字段值，可选地还能带另一个数据库名。

    @Getter private String street, zipCode, city, state;
}

public interface AddressRepository extends MongoRepository<Address, String> {
}

    @DBRef
    @Field("address")          // @Field 可以给文档里的字段起自定义名字

}

17.6 用 MongoTemplate 访问数据库

MongoTemplate 是一个提供针对 MongoDB 数据库的 CRUD 操作访问的类，它实现了 MongoOperations 接口。MongoOperations 里的方法命名与 MongoDB 驱动的 Collection 对象方法类似，以便于理解和使用这套 API。

17.6.1 配置

要把 Spring Boot 应用连到 MongoDB，我们继承 AbstractMongoClientConfiguration 类——它为 Spring Data MongoDB 提供了 Java 配置支持。这个抽象类已经提供了两个可用的 bean：

@Bean
public MongoTemplate mongoTemplate(MongoDatabaseFactory databaseFactory,
                                   MappingMongoConverter converter) {
    return new MongoTemplate(databaseFactory, converter);
}

@Bean
public MongoDatabaseFactory mongoDbFactory() {
    return new SimpleMongoClientDatabaseFactory(this.mongoClient(),
                                                this.getDatabaseName());
}

所以我们只需要覆写 getDatabaseName()：

Ch17/springdatamongodb3/.../configuration/MongoDBConfig.java
@Configuration
public class MongoDBConfig extends AbstractMongoClientConfiguration {
    @Override
    public String getDatabaseName() {
        return "test";
    }
}

17.6.2 用 MongoTemplate 执行 CRUD

插入——insert 方法是重载的，下面用的是接受一个对象、或接受对象集合加它们的类的版本：

mongoTemplate.insert(GenerateUsers.address);
mongoTemplate.insert(generateUsers(), User.class);

保存——save 的行为不同：如果 id 已经存在于数据库中，它执行更新；否则执行插入。

mongoTemplate.save(user, "user");

删除——我们用 org.springframework.data.mongodb.core.query.Query 对象来定义取回文档时的条件、投影和排序。用默认构造器创建的 Query 对应集合中的所有文档：

mongoTemplate.remove(new Query(), User.class);
mongoTemplate.remove(new Query(), Address.class);

构造条件——可以用不同的条件修改 Query 对象：

// 查 level 为 1 的用户
Query query = new Query();
query.addCriteria(Criteria.where("level").is(1));

// 查指定 username 且（AND）指定 email 的用户
Query query1 = new Query();
query1.addCriteria(Criteria.where("username").is("mike")
      .andOperator(Criteria.where("email").is("mike@somedomain.com")));

// 查指定 username 或（OR）指定 email 的用户
Query query2 = new Query(new Criteria().
               orOperator(Criteria.where("username").is("mike"),
                          Criteria.where("email").is("beth@somedomain.com")));

更新——用 org.springframework.data.mongodb.core.query.Update 类的对象，设上要替换旧值的新值：

updateFirst：更新第一个

Query query = new Query();
query.addCriteria(Criteria.where("level").is(1));

Update update = new Update();
update.set("level", 2);
mongoTemplate.updateFirst(query, update, User.class);

List<User> users = mongoTemplate.find(query, User.class);

找到 User 类中 level 为 1 的第一个文档并改成 level 2，然后可以用 find 拿到剩下的 level 1 用户。

updateMulti：更新全部

Query query = new Query();
query.addCriteria(Criteria.where("level").is(1));

Update update = new Update();
update.set("level", 2);
mongoTemplate.updateMulti(query, update, User.class);

找到 所有 level 为 1 的文档并全部改成 level 2。

findAndModify：返回旧值

Query query = new Query();
query.addCriteria(Criteria.where("level").is(1));

Update update = new Update();
update.set("level", 2);
User user = mongoTemplate.findAndModify(query, update, User.class);

assertEquals(1, user.getLevel());   // 拿到的是「修改前」的对象

upsert：更新或插入

Query query = new Query();
query.addCriteria(Criteria.where("level").is(1));

Update update = new Update();
update.set("level", 2);
UpdateResult result = mongoTemplate.upsert(query, update, User.class);

assertAll(
    () -> assertEquals(1, result.getMatchedCount()),   // 1 个文档匹配了查询
    () -> assertEquals(1, result.getModifiedCount()));  // 1 个文档被更新

找到就更新，找不到就合并 query 和 update 对象创建一个新文档。名字就是 update + insert，由 MongoDB 决定该做哪一个。

17.7 两种途径的对比

表 17.7　MongoRepository 与 MongoTemplate 对比
优点缺点
MongoRepository
  • 沿用 Spring Data JPA 和 Spring Data JDBC 仓库的路数，学习成本几乎为零
  • 能用查询构建器机制快速创建方法，靠方法名定义行为
  • 提供的方法执行基本 CRUD 操作，作用于文档的所有字段
  • 更新一个文档必须分步执行（find、改相关字段、save），或者用 @Query 注解的方法
MongoTemplate
  • 提供 updateFirst、updateMulti、findAndModify、upsert 这样的原子操作
  • 原子操作有利于并发应用中的工作
  • Update 对象允许我们只挑选要更新的字段
  • 更啰嗦、要写更多代码，简单操作尤其如此
实践建议

两者可以在同一个应用里共存。默认用 MongoRepository 处理绝大多数读取和简单写入；遇到「只想改一个字段」或「并发下必须原子」的场景，就注入 MongoTemplate 用 updateFirst / findAndModify。

本章小结

  • 可以用 Spring Boot 创建并配置一个 Spring Data MongoDB 项目。别忘了两条配置：把 MongoTemplate 日志级别设为 DEBUG 才看得到查询；把 auto-index-creation 设为 true 索引注解才生效。
  • 可以创建文档类并使用 Spring Data MongoDB 注解来定义简单索引和复合索引（@Indexed / @CompoundIndex）、把字段标记为 瞬时（@Transient，如密码），以及定义持久化构造器（@PersistenceConstructor，可配合 SpEL 提供默认值）。
  • 可以构建继承 MongoRepository 的自定义接口，按查询构建器机制创建自定义方法来与 MongoDB 交互。方法命名规则与 Spring Data JPA / JDBC 完全一致，只是被翻译成 JSON 查询过滤器。
  • 可以使用 Spring Data MongoDB 在限制查询结果、排序、分页和流式返回结果方面的能力——用法与前两章一模一样。
  • 可以用 @Query 注解定义自定义查询（value 定过滤器、fields 定投影、?0 占位符），也可以使用 Query by Example（QBE）查询技术——注意基本类型属性必须显式 withIgnorePaths。
  • 文档之间用 @DBRef 建立引用（$ref + $id），但没有嵌入文档，也没有级联——保存和删除被引用的文档必须显式进行。
  • 可以配置应用使用 MongoTemplate 执行 CRUD：它更啰嗦，但提供 原子的 updateFirst / updateMulti / findAndModify / upsert，并且能只更新指定字段。
